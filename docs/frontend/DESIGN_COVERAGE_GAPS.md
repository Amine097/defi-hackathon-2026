# Design coverage gaps: backend capabilities without a designed interface

Source of truth for the UI: the Claude Design v2 export in [`docs/design/claude-design-v2/`](../design/claude-design-v2/)
(`Faultline Landing v2.dc.html`, `Faultline App.dc.html`). The production pages (`public/index.html`, `public/app.html`)
render that export; nothing below was designed or built in its place. Each item is a request to bring back to Claude
Design. Matrix B in [COVERAGE_MATRICES.md](COVERAGE_MATRICES.md) lists every backend capability; this file keeps only
those that the approved design cannot show today.

Priority: **BLOCKING** (a relevant, implemented capability is unusable, or a reachable state has no truthful
presentation) · **IMPORTANT** (implemented and valuable for the Belem criteria, but invisible) · **OPTIONAL**.

Update (11 Oct 2026): G18–G20 are now shown in Countermove › tab 3 "Autonomous protection". There is no new design: the
existing design-target card and status-panel markup are reused and driven by data. The tab reads the hosted keeper
through `/api/countermove` (`FAULTLINE_KEEPER_URL`, see
[RAILWAY_KEEPER_DEPLOYMENT.md](../backend/RAILWAY_KEEPER_DEPLOYMENT.md)) and shows:

- the lifecycle state and gate checklist (G18)
- keeper health with heartbeat age (G19)
- the latest evidence rows with the hash-chain integrity badge (G20)

It is labelled LOCAL TEST and includes a permanent "RescueVault deployed on Ethereum mainnet: NO" row. Without a
reachable keeper, it falls back to the UNAVAILABLE design target. A dedicated design for these states is still open.

Frontend data gap (not a design gap): `fl-live.js` `qs()` drops empty parameters, so an ARM form with no strategy
selected sends no `strategies` key and the backend applies its default `REPAY,TOP_UP` instead of rejecting the draft.
The request should send `strategies=` explicitly (see [docs/backend/BACKEND_GAPS.md](../backend/BACKEND_GAPS.md)).

States reachable in production that reuse an existing designed state (no gap, documented for review):

- Analysis failure after "Start analysis" (HTTP 400/404/422/502/503, timeout) returns to the select screen in the
  designed **error** lookup state (ember message, Retry / Cancel) with the backend's message. No figures are shown.
- A firm STAY or EXIT verdict reuses the dashboard pill and tint vocabulary (cyan for STAY, ember for EXIT) that the
  design uses elsewhere; the design only drew REVIEW.
- A simulation whose shock does not reach the position (role-aware model: oracle or market failure on a position with
  no debt) shows **STAY** in the result's DECISION cell in cyan, with the backend's reason in the uncertainty column.
